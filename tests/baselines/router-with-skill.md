# 加载顶层 Skill 的路由基线

每个场景均在彼此隔离的新鲜上下文中执行。评测器只完整读取顶层 `SKILL.md`，不读取任务简报、其他文件或先前会话。输入均来自 `tests/evals/router.json` 的匿名合成夹具，不包含真实用户、可识别个人或真实企业信息，也不代表用户确认事实。以下原始输出逐字记录。

## resume-only

```text
你这次更需要通用修改润色，还是根据具体JD定制简历？
```

## jd-only

```text
这个岗位本质上是一个偏 B 端、以增长结果为导向的产品经理岗位，不只是做常规需求迭代。

- 核心工作：围绕转化漏斗规划增长产品、分析需求、推动版本上线，并复盘效果。
- 核心能力：B 端产品经验、数据分析、跨研发/设计/运营/销售的项目推进。
- 硬性门槛：[用户提供] 5 年以上 B 端产品经验。
- 评估重点：是否有明确的增长场景、漏斗指标、数据驱动决策，以及跨部门推动后取得的业务结果。

如果你的经历主要是后台系统、权限、流程或企业客户产品，应重点说明这些工作如何影响获客、激活、转化、留存或销售效率；若没有直接增长项目，需要标注为 [待确认]，避免把常规产品迭代包装成增长成果。
```

## review-direct

```text
以下仅基于已提供材料评审；未出现的信息均标为 [待确认]。

**HR 视角**

匹配点：
- [用户提供] 有数据分析师与运营专员经历，职业轨迹与目标岗位一致。
- [用户提供] 使用 SQL 提取订单与用户数据，并参与销售看板搭建，具备基础数据工作关键词。

主要风险：
- 缺少业务成果：周报、数据提取、看板均未说明服务对象、使用频率、覆盖范围或实际业务影响。[待确认]
- SQL 能力描述较浅，未体现复杂分析、数据建模、指标体系或数据质量处理能力。[待确认]
- 简历没有展示常用分析工具、可视化工具、学历背景及项目产出，不利于通过初筛。[待确认]

HR 结论：具备基础匹配，但当前表达更像“数据支持执行者”，需要补足可量化产出与能力关键词。

**部门负责人视角**

可取之处：
- [用户提供] 接触订单、用户、销售等业务数据，具备业务分析的潜在场景。
- [用户提供] 有看板协作经历，说明可能理解业务团队的数据使用需求。

主要疑问：
- 候选人是独立定义问题和指标，还是仅按要求取数、出表？[待确认]
- 是否通过分析发现过问题、提出过建议，并推动业务动作？[待确认]
- 看板的核心指标、数据口径、使用人群及上线后的效果均未说明。[待确认]
- 缺少统计分析、实验分析、专题分析或经营决策支持案例。[待确认]

部门负责人结论：现有证据不足以判断独立分析与业务影响能力。建议每段经历按“业务问题—分析动作—结论/方案—量化结果”重写，并只使用可由候选人确认的真实数据。
```
